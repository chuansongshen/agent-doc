# 第10章：企业级 RAG 评测

## ① 核心知识点

- 评测分层：数据质量、检索（Recall@K/Precision@K/MRR/nDCG）、生成（忠实性、相关性、完整性）、系统（延迟、成本、稳定性）和业务（解决率、转人工率）。
- 建立带权限和版本的黄金集：问题、期望证据、参考答案、不可回答标签、风险等级；覆盖正常、边界、对抗和多语言。
- 离线评测用于选模型/切分/检索参数，线上评测用于漂移、真实满意度和事故监控；二者不能互相替代。
- LLM-as-a-Judge 要求明确评分量表、引用证据、抽样人工复核和偏差校准。
- 发布门禁看“关键集不回退 + 成本/延迟在 SLO 内”，不要只追单一总分。

## ② 原理

检索 Recall@K = 命中的必要证据数/必要证据总数；生成忠实性检查答案声明是否被证据蕴含，相关性检查是否回答问题，完整性检查关键点覆盖。将测试集按意图、租户、文档版本分层，固定随机种子和评测配置。每次变更记录模型、Prompt、索引、数据快照；用置信区间或 bootstrap 判断差异是否稳定。线上采用分桶、抽样和用户反馈，发现高风险错误立即阻断自动化。

## ③ 企业架构

```text
黄金集/线上样本 → Eval Runner → 检索指标 + 生成指标 + 性能成本
                           ├→ 人工复核与裁判校准
                           └→ 报告/门禁 → 灰度发布
线上 Trace → 脱敏采样 → 漂移检测、告警、回流数据集
```

评测服务读取不可变数据快照，调用与生产相同的 Retriever/Prompt/Model；结果写入实验库，支持按版本对比。高风险样本（法律、财务、权限）必须人工双审，自动裁判只做初筛。指标仪表盘展示 p50/p95 延迟、token、单位请求成本和拒答率。

## ④ 面试标准答案

> 企业级 RAG 评测要把“找得到、答得对、用得起、守得住”拆开：检索看 Recall/ nDCG，生成看忠实性、相关性和完整性，系统看 p95 延迟、成本和错误率，业务看解决率与转人工。用带证据和版本的黄金集做离线回归，线上抽样结合用户反馈；LLM 裁判需量表、校准和人工复核。上线门禁要求关键集不回退并满足安全、SLO 和预算。

## ⑤ 高频追问

1. **没有标准答案怎么办？** 标注必要证据和可接受要点，或只评检索与引用；不可回答题单独计分。
2. **LLM 裁判可靠吗？** 不能盲信；使用结构化 rubric、双模型/人工抽样、位置和长度偏差检查。
3. **Recall 高但用户仍不满意？** 可能重排、上下文拼装或生成忠实性差，按链路拆分定位。
4. **如何评估权限？** 构造跨租户/离职/越权样本，指标包括越权拦截率和敏感证据泄露为零。

## ⑥ 场景题

**场景：客服 RAG 发布新 embedding。** 从历史工单抽取 1000 条问题，标注 2 名专家的证据和答案要点，按产品线分层。比较基线与候选的 Recall@20、nDCG@5、忠实性、p95 和成本；关键退款/合规题设零容忍。通过后 5% 流量灰度，监控负反馈和转人工，异常自动回滚。

## ⑦ 生产事故题

**事故：离线分数上升但线上投诉增加。** 调查发现测试集只含公开文档，未覆盖新版本和真实权限；裁判偏好更长答案。暂停扩量，回放线上脱敏样本并补充版本/ACL/不可回答题，重新标注 rubric；修正门禁为分层指标和人工抽检。验证：线上负反馈率恢复基线，越权样本拦截率 100%，持续一周无回退。

## ⑧ 常见错误回答

- “BLEU/ROUGE 高就说明 RAG 正确”——词面重合不能证明证据和事实。
- “只评最终答案”——无法区分检索、重排、上下文和生成问题。
- “LLM 裁判给 0~10 分即可”——没有标准和校准，分数不可比。
- “一次离线评测通过就能上线”——数据、模型和用户分布会漂移，必须持续线上监控。

## ⑨ Java/Python 实现思路

```python
for case in dataset:
    out = rag.invoke(case.question, user=case.user)
    recall = recall_at_k(out.retrieved_ids, case.gold_evidence, 20)
    faith = judge_faithfulness(out.answer, out.citations, rubric=RUBRIC)
    rows.append({"id": case.id, "recall@20": recall,
                 "faithfulness": faith, "latency_ms": out.latency,
                 "cost": out.cost})
report = aggregate_by_intent(rows)
assert report["critical"]["faithfulness"] >= 0.95
```

Java 可用 JUnit 参数化测试或独立 Eval Runner，读取 JSONL 黄金集，结果写 CSV/数据库；生产 Trace 脱敏后按固定比例回流，避免把用户隐私直接纳入训练或评测。

## ⑩ 权衡与最佳实践

- 自动指标便宜可规模化，人工评审更可信；高风险场景采用“自动全量 + 人工抽样/双审”。
- 更大的测试集提升置信度但成本高；先覆盖关键意图和风险，再逐步扩充长尾。
- 单一总分会掩盖租户和意图差异；报告分层分布、置信区间及最差分位。
- 评测代码、数据快照和配置一起版本化，确保结果可复现；门禁阈值随业务风险设定。
